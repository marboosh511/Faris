# مملكة الخيل — الإصدار 5.74 (حزمة تجهيز الخادم)

هذه الحزمة تبدأ تجهيز الخادم الحقيقي للعبة اعتماداً على الأنظمة الموجودة فقط: حساب اللاعب، منقية الخيل، سوق الخيل، وتسجيل الخيل في البطولات. لا توجد بيانات لاعبين وهمية ولا خيول تجريبية مزروعة في قاعدة البيانات.

## ما الموجود؟
- `index.html`: واجهة اللعبة الحالية كما كانت في v5.73.
- `server/`: واجهة API بخادم Node.js وقاعدة PostgreSQL.
- تسجيل حساب وتسجيل دخول بكلمات مرور مشفّرة ورمز جلسة.
- حفظ ملف اللاعب وخيوله في قاعدة البيانات.
- سوق مشترك مع نقل ملكية الحصان عند الشراء داخل معاملة قاعدة بيانات.
- تسجيل الخيول في البطولات ومنع تكرار تسجيل الحصان نفسه في البطولة نفسها.
- حماية أساسية: تحقق من المدخلات، تحديد محاولات تسجيل الدخول، CORS، Helmet.

## تشغيل تجريبي على جهاز يملك Docker
1. ادخل مجلد `server`.
2. غيّر كلمة مرور PostgreSQL و`JWT_SECRET` في `docker-compose.yml` إلى قيم سرية قوية.
3. اضبط `CORS_ORIGIN` على نطاق اللعبة الفعلي.
4. شغّل: `docker compose up --build -d`
5. اختبر: `https://عنوان-الخادم/health` ويجب أن يرجع `{"ok":true,...}`.

## ما الذي لم يتم بعد؟
- الخادم غير منشور على الإنترنت، ولا توجد قاعدة بيانات مستضافة بعد.
- واجهة HTML الحالية لم تُربط بعد بواجهات API؛ لذلك تظل تعمل محلياً كما في v5.73 حتى يتم إنشاء الخادم وتزويدي بعنوانه العام وإعداداته العامة.
- لم نفعّل نظام دفع أو عملات أو مزادات بوقت حقيقي، ولم نخترع قواعد تربية أو نتائج بطولات غير موثقة.

## الخطوة المطلوبة منك الآن
أنشئ خدمة استضافة للخادم وقاعدة PostgreSQL (أو وفّر VPS يدعم Docker). لا ترسل كلمة مرور قاعدة البيانات أو `JWT_SECRET` في المحادثة. بعد إنشاء الخدمة أرسل فقط:
- عنوان API العام (مثلاً `https://api.example.com`)
- اسم مزود الاستضافة الذي اخترته
- هل قاعدة PostgreSQL أُنشئت بنجاح؟

بعدها نكمل ربط الواجهة بالـ API واختبار التسجيل والسوق والبطولات. لا يمكن تشغيل تعدد اللاعبين فعلياً قبل هذه الخطوة.
